# HP ERP 테스트 계획과 결과

> 개발 단계: **⑥ 테스트** · 산출물: 테스트 케이스 시트(TC), 결함 리포트, 테스트 결과 보고서
> 관련 다이어그램: [Communication 다이어그램](./ARCHITECTURE.md#7-communication-다이어그램-결재-승인)

## 1. 원칙

- **사실대로 기록합니다.** 통과하지 못한 검사는 통과하지 못했다고 적습니다.
- 자동 테스트가 없는 핵심 흐름은 **수동 TC**로 매 배포 전에 확인합니다.
- 버그를 고치면 같은 커밋에 그 버그를 잡는 테스트(또는 TC)를 추가합니다.

## 8. 로딩 성능 개선 검증 (2026-10-29, `feature/loading-performance`)

브랜치는 develop을 거쳐 2026-10-30에 운영(main `c2b8a6c`, Apps Script @59)에 반영했습니다. 대상 커밋은 `2a81c2a`(로딩 병목·API 재시도 정리), `741691f`(편집기에서만 고쳐져 있던 Apps Script 수정 반영: 실제 그룹 이메일, 공지 이미지 디코딩), `69ee162`(QA 결함 수정), `940670c`(프론트 그룹 이메일 기본값 수정)입니다. 구조는 [ADR-013](./ADR.md#adr-013-스프레드시트-id를-drive-검색-1회와-서버-캐시로-찾는다)에 있습니다.

### 8.1 원인

- 기존 `getSpreadsheetIds`는 이름 하나마다 루트 폴더 트리 전체를 재귀 탐색했습니다. 이름 8개면 트리를 8번 돌았고, 서버 캐시도 없었습니다.
- 운영 배포 @34에서 이 호출 한 번이 **49.4초** 걸렸습니다. Netlify 동기 함수는 10초에서 끊기므로, 사이트를 통한 호출은 거의 항상 시간 초과 후 재시도했을 것으로 봅니다.
- 클라이언트는 타임아웃 60초, 재시도 5회였고 재시도마다 같은 중단 신호를 써서 한 번 타임아웃되면 남은 재시도가 즉시 실패했습니다(BUG-06).
