# HP ERP 런북 (장애 대응)

> 개발 단계: **⑦ 수정 및 문서화** · 산출물: 장애 대응 가이드
> 대상: 운영자(조교), 개발 담당자

각 항목은 **대상·조건 → 사전 확인 → 절차 → 판단·분기 → 해결되지 않을 때 → 완료 확인** 순서로 적었습니다.

## 0. 공통 사전 확인

장애 신고를 받으면 먼저 아래를 확인합니다.

| 확인 | 방법 |
|---|---|
| 영향 범위 | 한 사람만인가, 전체인가? 다른 계정·브라우저에서도 같은가? |
| 증상 화면 | 사용자에게 화면 캡처와 **개발자 도구(F12) → Console** 캡처를 받습니다 |
| 최근 변경 | Netlify **Deploys**의 마지막 배포 시각, Apps Script **배포 관리**의 버전, 최근 커밋 |
| 필요 권한 | Netlify 사이트 관리자, Apps Script 배포 계정, Google Cloud OAuth 클라이언트 편집 권한 |

| 확인 위치 | 볼 것 |
|---|---|
| 브라우저 Console | `API 요청 시도`, `API 응답 성공`, 빨간 오류 |
| 브라우저 Network | `/.netlify/functions/proxy`의 상태 코드와 응답 본문 |
| Netlify → Logs → Functions → `proxy` | `APP_SCRIPT_URL 환경변수 누락`, `Apps Script가 JSON이 아닌 응답을 반환했습니다.`, `Apps Script 요청 시간 초과`(브랜치 `feature/loading-performance` 이후). 로그에는 메서드와 `action`만 남습니다 |
| Apps Script → 실행 | 실패한 `doPost` 실행과 오류 메시지 |

## RB-01 모든 기능에서 데이터가 안 불러와짐

**대상·조건:** 전체 사용자에게 공지·결재·문서가 비어 있거나 오류 알림이 뜹니다.

**절차:**
1. Network 탭에서 `/.netlify/functions/proxy` 응답을 확인합니다.
2. 응답에 따라 분기합니다.

**판단·분기:**

| 응답 | 원인 | 조치 |
|---|---|---|
| 500 `Apps Script URL이 설정되지 않았습니다.` (배포 직후 모든 API) | Netlify에 `APP_SCRIPT_URL`이 없음. 프록시는 `VITE_APP_SCRIPT_URL`을 대신 읽지 않음 | Netlify 환경변수에 `APP_SCRIPT_URL` 추가 → **Clear cache and deploy** |
| 504 `Apps Script 응답 시간이 초과되었습니다.` (`retryable:true`) | Apps Script가 약 9초 안에 답하지 못함. 프록시가 Netlify 10초 제한 전에 끊은 것 | 앱이 조회 요청은 자동으로 최대 2회 다시 시도합니다. 계속되면 Apps Script **실행**에서 해당 액션의 실행 시간을 확인. `getSpreadsheetIds`가 느리면 서버 캐시가 비었거나 Drive 검색이 실패해 폴더 탐색으로 넘어간 경우이므로 RB-08 확인. 쓰기 요청은 재시도하지 않으므로 사용자에게 결과를 확인한 뒤 다시 하라고 안내 |
| 502·504 HTML 오류 페이지 (Netlify 자체 응답) | 브랜치 이전 프록시에서 Apps Script가 10초를 넘김 | 위와 같음. `feature/loading-performance` 병합 후에는 위 504 JSON으로 바뀜 |
| `Apps Script가 JSON이 아닌 응답을 반환했습니다.` | Apps Script가 HTML(로그인·권한·오류 페이지)을 돌려줌. 배포가 삭제됐거나, 접근 권한이 바뀌었거나, URL이 옛날 배포를 가리킴 | Apps Script **배포 관리**에서 활성 배포 URL을 확인하고 `APP_SCRIPT_URL`과 비교 → 다르면 고치고 재배포 |
| 502 `Apps Script 연결 중 오류가 발생했습니다.` | 네트워크 또는 Google 측 일시 장애 | 5분 후 재시도. [Google Workspace 상태 대시보드](https://www.google.com/appsstatus) 확인 |
| 200 + `success:false`, `알 수 없는 액션입니다` | 프론트가 백엔드에 없는 액션을 호출. 프론트만 먼저 배포됐을 가능성 | 백엔드 `clasp push` + 새 버전 배포, 또는 Netlify 이전 배포로 롤백 |
| 200 + `success:false`, 그 외 메시지 | 액션 처리 중 오류 | Apps Script **실행** 로그에서 해당 시각의 오류 확인 → RB-03 또는 개발 담당자 |

**해결되지 않을 때:** 직전 배포를 롤백합니다(Netlify **Publish deploy**, Apps Script 이전 버전). 그래도 안 되면 개발 담당자에게 Console·Network 캡처와 Functions 로그를 전달합니다.

**완료 확인:** 새 창에서 로그인 → 공지사항 목록이 보이고 proxy 응답이 `success:true`.

## RB-02 로그인이 안 되거나 자꾸 로그아웃됨

**대상·조건:** 로그인 버튼을 눌러도 앱으로 못 돌아오거나, 사용 중에 로그아웃됩니다.

**판단·분기:**

| 증상 | 원인 | 조치 |
|---|---|---|
| Google 화면에 `redirect_uri_mismatch` | 접속 주소가 OAuth 클라이언트에 등록되지 않음 (도메인 변경, 새 포트) | Google Cloud Console → OAuth 클라이언트 → 원본과 리디렉션 URI에 현재 주소 추가. 반영까지 몇 분 걸릴 수 있음 |
| Google 화면에 `access_denied` 또는 "앱이 확인되지 않음" | OAuth 동의 화면이 테스트 모드이고 사용자가 테스트 사용자가 아님 | 동의 화면을 게시하거나 테스트 사용자에 추가 |
| 약 1시간 후 "토큰이 만료되었습니다" 알림과 함께 로그아웃 | 현재 로그인 방식(implicit flow)은 토큰을 자동 갱신하지 못함. **정상 동작** | 다시 로그인하라고 안내. 개선 과제는 [STATUS.md](./STATUS.md) |
| 30분 동안 아무것도 안 했더니 로그아웃 | 무활동 세션 만료. **정상 동작** | 다시 로그인 |
| 로그인 후 계속 승인 대기 화면 | 아직 승인되지 않았거나, 승인됐지만 화면이 새로 고쳐지지 않음 | `user` 시트에서 `Approval` 확인 → `O`면 로그아웃 후 다시 로그인 |
| 가입 신청 시 "해당 학번에 일치하는 사용자를 찾을 수 없습니다" | 사전 등록이 안 됐거나 이름이 다름 | [OPERATOR_MANUAL §3.1](./OPERATOR_MANUAL.md#31-사전-등록)대로 사전 등록, 이름 철자 확인 |

**완료 확인:** 해당 사용자가 대시보드까지 들어옵니다.

## RB-03 "데이터 로딩 중"에서 멈추거나 특정 화면이 비어 있음

**대상·조건:** 로그인 후 "스프레드시트 ID 초기화 중…" 진행 표시가 오래 멈춰 있거나, Console에 `... spreadsheet ID not found`, `스프레드시트를 찾을 수 없습니다` 경고가 나옵니다.

**사전 확인:** 배포 계정으로 Google Drive에 들어가 `hot_potato_remake/` 폴더 구조를 확인합니다([DATA_MODEL.md §4](./DATA_MODEL.md#4-drive-폴더-구조)).

**절차:**
1. Console에서 어떤 스프레드시트 ID를 못 찾았는지 확인합니다(예: `Announcement spreadsheet ID not found` → `notice`).
2. Drive에서 그 파일이 **정확한 이름**으로, **루트 폴더 아래**에 있는지 확인합니다.
3. Apps Script 스크립트 속성 `ROOT_FOLDER_ID`가 실제 루트 폴더 ID와 같은지 확인합니다.
4. 사용자가 그 파일에 접근 권한이 있는지 확인합니다. 캘린더·학생·교직원·장부는 브라우저에서 사용자 권한으로 직접 읽습니다.

**판단·분기:**

| 확인 결과 | 조치 |
|---|---|
| 파일이 없음 | Apps Script에서 `initializeSystem` 다시 실행. 있는 파일은 건너뛰고 없는 것만 만듭니다 |
| 이름이 다름 | 원래 이름으로 되돌리거나, 환경변수(`VITE_SPREADSHEET_NAME`)와 스크립트 속성을 함께 바꾼 뒤 재배포 |
| 같은 이름 파일이 여러 개 | 하나만 남기고 이동·삭제. 첫 번째로 찾은 파일만 쓰입니다 |
| 사용자에게 권한이 없음 | 해당 파일·폴더를 사용자 또는 역할 그룹에 공유. 승인 때 그룹 추가가 실패했는지 `group_management_log` 확인 |
| 진행 표시만 멈추고 오류가 없음 | 헤더 새로고침 버튼 또는 브라우저 새로고침. 계속되면 RB-04 확인 |

**해결되지 않을 때:** Console 전체 로그를 저장해 개발 담당자에게 전달합니다.

**완료 확인:** 로딩 표시가 사라지고 해당 화면 데이터가 보입니다.

## RB-04 느려지거나 "요청이 너무 많습니다"

**대상·조건:** 응답이 매우 느리거나, Console에 `429`, `sync429Error`, `quota`가 나옵니다.

**원인:** Apps Script와 Google API는 계정별 호출 할당량이 있습니다. 학기 초처럼 사용자가 몰리면 초과할 수 있습니다.

**절차:**
1. 앱이 스스로 대응합니다. 재시도할 때는 서버가 알려 준 대기 시간을 지키고, 해당 데이터의 주기 동기화를 30~120분 멈춥니다.
2. 사용자에게 잠시 후 다시 시도하라고 안내합니다. 새로고침을 반복하면 더 늦어집니다.
3. Apps Script **실행** 화면에서 실패 비율과 6분 초과(`Exceeded maximum execution time`) 오류를 확인합니다.

**판단·분기:** proxy 응답이 504 `Apps Script 응답 시간이 초과되었습니다.`이면 할당량이 아니라 느린 액션 문제입니다. RB-01의 504 행을 따릅니다.

**해결되지 않을 때:** 하루 단위 할당량을 넘었으면 다음 날 자동으로 풀립니다. 반복되면 개발 담당자에게 캐시 TTL 조정을 요청합니다([ARCHITECTURE.md §9.2](./ARCHITECTURE.md#92-데이터-로딩과-캐시)).

**완료 확인:** 새로 연 창에서 공지사항이 10초 안에 보입니다.

## RB-05 관리자 키가 없거나 메일이 안 옴

**대상·조건:** 관리자 키 메일이 오지 않거나 "관리자 키가 없습니다" 류의 오류가 납니다.

**절차:**
1. Apps Script **트리거**에 `handleDailyKeyUpdate`(일 단위)가 있는지 확인합니다. 없으면 만듭니다.
2. `hp_member.admin_keys` 시트 2행에 키가 있는지 확인합니다. 없으면 편집기에서 `handleDailyKeyUpdate`를 한 번 실행합니다.
3. 메일이 안 오면 받는 사람의 스팸함을 확인하고, Apps Script **실행** 로그에서 Gmail 발송 오류(일일 발송 한도 등)를 봅니다.

**완료 확인:** 관리자 키 메일이 도착합니다.

## RB-06 결재·문서 링크를 열면 "액세스 권한 필요"

**대상·조건:** 결재선에 있는데 문서를 열 수 없습니다.

**절차:**
1. 결재 요청자에게 문서가 **공유 문서**인지 **개인 문서**인지 확인합니다. 개인 문서는 요청자 브라우저에서 권한을 부여합니다.
2. 요청자의 문서를 Drive에서 열고 **공유**에 결재 참여자가 있는지 확인합니다.
3. 없으면 요청자가 직접 보기 권한으로 공유합니다.

**완료 확인:** 결재 참여자가 문서를 엽니다.

## RB-07 잘못된 배포 되돌리기

**대상·조건:** 배포 직후 기능이 깨졌습니다.

**절차:**

| 대상 | 롤백 |
|---|---|
| 프론트엔드 | Netlify **Deploys** → 직전 정상 배포 → **Publish deploy** |
| Apps Script | **배포 관리 → 기존 배포 편집 → 버전**에서 직전 버전 선택 → 배포 (URL 유지) |
| 환경변수 | Netlify 환경변수를 이전 값으로 되돌림 → Clear cache and deploy |

**판단·분기:** 프론트와 백엔드를 같이 배포했다면 **둘 다** 이전 버전으로 돌립니다. 한쪽만 돌리면 액션 이름이 어긋날 수 있습니다.

**완료 확인:** [DEPLOYMENT.md §6](./DEPLOYMENT.md#6-배포-후-확인) 체크리스트를 다시 통과합니다.

## RB-08 시트를 바꾼 뒤 옛 데이터나 빈 화면이 보임

**대상·조건:** 스프레드시트 파일을 새로 만들어 교체했거나, 다른 폴더로 옮겼거나, 이름을 바꾼 뒤 해당 화면이 비어 있거나 예전 파일 내용이 보입니다. 브랜치 `feature/loading-performance` 이후 코드에 해당합니다.

**원인:** Apps Script가 스프레드시트 ID를 서버 캐시에 6시간, 브라우저가 클라이언트 캐시에 6시간 보관합니다([ADR-013](./ADR.md#adr-013-스프레드시트-id를-drive-검색-1회와-서버-캐시로-찾는다)). 파일이 바뀌어도 그동안은 옛 ID를 씁니다.

**사전 확인:** 새 파일이 정확한 이름으로 루트 폴더 아래에 있고, 같은 이름의 다른 파일이 없는지 확인합니다(RB-03).

**절차:**
1. 배포 계정으로 Apps Script 편집기를 열고 `SpreadsheetUtils.gs`의 `clearSpreadsheetIdCache`를 실행합니다. 로그에 `스프레드시트 ID 캐시를 비웠습니다.`가 나오면 됩니다.
2. 사용자에게 헤더의 새로고침 버튼(캐시 초기화)을 누른 뒤 **브라우저를 새로고침(F5)** 하라고 안내합니다. 한 탭 안에서는 ID를 메모리에 기억하므로 새로고침 버튼만으로는 ID를 다시 조회하지 않고, 로그아웃은 캐시를 지우지 않습니다.

**판단·분기:**

| 결과 | 조치 |
|---|---|
| 새 ID로 정상 표시 | 완료 |
| 여전히 빈 화면, Console에 `spreadsheet ID not found` | 파일 위치·이름 문제. RB-03 |
| `ROOT_FOLDER_ID`를 바꿨음 | 스크립트 속성을 고친 뒤 1번을 다시 실행. 루트 폴더 캐시도 함께 지워짐 |

**해결되지 않을 때:** 브라우저 개발자 도구 → Application → Local Storage에서 `cache_`로 시작하는 항목을 지우고 새로고침합니다. 그래도 안 되면 개발 담당자에게 Console 로그를 전달합니다.

**완료 확인:** 해당 화면에 새 파일의 데이터가 보입니다.
