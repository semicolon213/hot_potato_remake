# HP ERP 보안

> 개발 단계: **④ 구조 생성**(보안 정책) · **⑦ 수정 및 문서화**
> 이 문서는 보안 **설계와 운영 원칙**을 다룹니다. 구체적인 취약점 내용은 공개 저장소에 적지 않습니다([§6](#6-취약점-신고)).

## 1. 인증

| 항목 | 내용 |
|---|---|
| 로그인 | Google OAuth 2.0. 별도 비밀번호를 저장하지 않음 |
| 토큰 저장 | 브라우저 `localStorage`의 `googleAccessToken` (만료 시각 포함). URL에 담겨 온 토큰은 받은 즉시 주소창에서 지움 |
| 토큰 만료 | 만료 1분 전부터 무효로 보고 다시 로그인을 요구함. 최대 세션 약 1시간 |
| 무활동 만료 | 30분 동안 활동이 없으면 로그아웃 |
| Apps Script 호출 | 사용자 토큰을 Apps Script로 보내지 않음. Apps Script는 배포 계정 권한으로 실행 |

## 2. 접근 제어

### 2.1 가입 단계

1. **사전 등록:** 관리자가 등록한 학번·이름과 일치해야 가입을 신청할 수 있습니다.
2. **관리자 승인:** 승인 전에는 승인 대기 화면 외에 아무것도 볼 수 없습니다.
3. **관리자 권한:** 매일 바뀌는 관리자 키가 있어야 신청할 수 있습니다.

| 경로 | 보호 수단 |
|---|---|
| 브라우저에서 Sheets·Drive 직접 접근 (장부, 캘린더, 학생, 개인 설정) | **Google Drive 공유 권한**. 공유받지 않은 파일은 읽을 수 없음 |
| Apps Script 경유 (회원, 공지, 결재, 공유 문서) | Apps Script 안의 검사 로직 |
| 화면 | 역할에 따라 메뉴·버튼 표시 (보조 수단. 화면 숨김만으로 권한을 보장하지 않음) |

## 3. 데이터 보호

| 대상 | 보호 방법 |
|---|---|
| 회원 이메일, 공지 작성자 이메일 | 저장 시 다층 변환 후 저장 (`EncryptionEmail.gs`) |
| 학생 연락처, 교직원 연락처·이메일 | 위와 같음 |
| 관리자 키 | 다층 변환 후 저장, 매일 교체 |
| Apps Script 웹앱 주소 | Netlify 서버 전용 환경변수 `APP_SCRIPT_URL`. 클라이언트 번들에 넣지 않음 |
| 공용 데이터 원본 | 배포 계정 드라이브. 역할 폴더별로 그룹에 공유 |

현재 저장 시 변환은 Apps Script 안에 있는 알고리즘 조합입니다. 표준 암호화(키 관리가 분리된 AES 등)로 바꾸는 것을 개선 과제로 둡니다([§5](#5-개선-계획)).

### 공개되는 값

`VITE_`로 시작하는 환경변수는 빌드할 때 브라우저 번들에 들어갑니다. OAuth 클라이언트 ID, 폴더·시트 이름, 그룹 이메일이 여기에 해당하며, **공개되어도 되는 값만** 넣습니다.

## 4. 운영 보안 수칙

- Apps Script **배포 계정**은 학과 공용 계정으로 하고, 2단계 인증을 켭니다. 이 계정이 모든 공용 데이터의 소유자입니다.
- `hp_member` 스프레드시트는 배포 계정 외에 공유하지 않습니다.
- 퇴직·졸업자는 Google 그룹에서 빼고, `user` 시트의 `Approval`을 비웁니다.
- 장부 폴더 공유는 장부 관리인과 필요한 그룹으로만 제한합니다.
- 관리자 키는 메일로만 전달하고, 메신저 등에 붙여 넣지 않습니다.
- 시트를 직접 수정할 때 암호화된 열을 평문으로 덮어쓰지 않습니다.
- 개인정보 처리 근거는 `/privacy`(개인정보처리방침), 서비스 조건은 `/terms`(이용약관)에 게시합니다.

## 5. 개선 계획

코드 점검(2026-10-27)에서 나온 보안 개선 과제의 **분류**입니다. 세부 내용과 우선순위는 비공개로 관리합니다.

| 분류 | 방향 |
|---|---|
| 서버 측 인가 | Apps Script가 요청자의 신원을 직접 확인하도록 바꿉니다 (예: ID 토큰 검증). 관리 기능은 모두 서버에서 관리자 여부를 다시 확인합니다 |
| 화면 접근 | 페이지 단위로 권한을 검사합니다. 메뉴 숨김에만 의존하지 않습니다 |
| 개인정보 저장 | 표준 암호화 방식으로 바꾸고, 복호화는 필요한 서버 로직 안에서만 합니다 |
| 키 관리 | 관리자 키를 암호학적 난수로 만들고, 검증 로직을 하나로 합칩니다 |
| 로그인 방식 | implicit flow를 Authorization Code + PKCE로 바꿔 토큰 갱신과 세션 유지 시간을 개선합니다 |
| 오류 응답 | 운영 환경 오류 응답에서 스택·디버그 정보를 뺍니다 |
| 로그아웃 | 로그아웃할 때 캐시와 사용자 데이터를 모두 지웁니다 |
