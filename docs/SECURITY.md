# HP ERP 보안

> 개발 단계: **④ 구조 생성**(보안 정책) · **⑦ 수정 및 문서화**
> 이 문서는 보안 **설계와 운영 원칙**을 다룹니다. 구체적인 취약점 내용은 공개 저장소에 적지 않습니다([§6](#6-취약점-신고)).

## 1. 인증

| 항목 | 내용 |
|---|---|
| 로그인 | Google OAuth 2.0. 별도 비밀번호를 저장하지 않음 |
| 토큰 저장 | 브라우저 `localStorage`의 `googleAccessToken` (만료 시각 포함). URL에 담겨 온 토큰은 받은 즉시 주소창에서 지움 |
| 토큰 만료 | 만료 1분 전부터 무효로 보고 다시 로그인을 요구함. 최대 세션 약 1시간 |
| 무활동 만료 | 30분 동안 활동이 없으면 로그아웃 |
| Apps Script 호출 | 요청마다 현재 액세스 토큰을 `accessToken` 필드로 보냄. Apps Script는 Google tokeninfo로 토큰을 확인해 이메일만 얻고, 토큰을 저장하거나 로그에 남기지 않음. 확인한 이메일은 토큰 해시를 키로 최대 5분 캐시. 실제 작업은 배포 계정 권한으로 실행 |
| 토큰 확인 조건 | `aud` 또는 `azp`가 스크립트 속성 `GOOGLE_CLIENT_ID`와 같음, `email_verified`, 만료 전. 하나라도 어긋나면 요청자를 확인하지 못한 것으로 봄 |

## 2. 접근 제어

### 2.1 가입 단계

1. **사전 등록:** 관리자가 등록한 학번·이름과 일치해야 가입을 신청할 수 있습니다.
2. **관리자 승인:** 승인 전에는 승인 대기 화면 외에 아무것도 볼 수 없습니다.
3. **관리자 권한:** 매일 바뀌는 관리자 키가 있어야 신청할 수 있습니다.
4. **서버 측 인가:** Apps Script는 액션을 공개·회원·관리자로 나눕니다(`appScript/Authz.gs`의 `PUBLIC_ACTIONS_`, `ADMIN_ACTIONS_`, 나머지는 회원). 회원 액션은 토큰으로 확인한 이메일이 `hp_member`에 승인된 회원일 때만, 관리자 액션은 그 회원이 관리자일 때만 처리합니다. `userType`과 관리자 여부는 `hp_member`에서 읽고, 브라우저가 보낸 값은 무시합니다. 실패하면 `AUTH_REQUIRED`, `MEMBER_REQUIRED`, `ADMIN_REQUIRED`를 돌려줍니다([ADR-015](./ADR.md#adr-015-apps-script가-액세스-토큰으로-요청자를-확인한다)).

### 2.3 권한을 지키는 곳

| 경로 | 보호 수단 |
|---|---|
| 브라우저에서 Sheets·Drive 직접 접근 (장부, 캘린더, 학생, 개인 설정) | **Google Drive 공유 권한**. 공유받지 않은 파일은 읽을 수 없음. 역할 폴더 권한은 Google 그룹 가입으로 생기며, `hp_member`의 `user_type`은 앱 화면과 API에서만 쓰고 Drive 권한을 바꾸지 않음. 역할 폴더는 브라우저가 Sheets API로 직접 쓰기 때문에 그룹에 편집 권한으로 공유함(의도된 설정) |
| OAuth 범위 | `drive.file`(이 앱이 만든 파일만), `spreadsheets`, `calendar.events`, `calendar.readonly`, `profile`, `email`만 요청. Gmail·Docs 범위는 요청하지 않음 |
| Apps Script 경유 (회원, 공지, 결재, 공유 문서, 공지 첨부, 증빙 업로드, 양식 내보내기) | 서버 측 인가(§2.1의 4)와 기능별 검사. 공지 첨부·증빙 업로드는 승인 회원만, 서버에서 4MB 제한, 공지 첨부는 허용 형식만. 양식 내보내기·미리보기는 `shared_forms` 바로 아래 파일만. 이름으로 찾은 시스템 스프레드시트는 배포 계정 소유일 때만 씀 |
| 화면 | 역할에 따라 메뉴·버튼 표시 (보조 수단. 화면 숨김만으로 권한을 보장하지 않음) |
| 설치 마법사 `/install/` | 별도 설치용 클라이언트로 `script.projects`, `script.deployments`, `userinfo.email`만 요청. 본 앱은 이 범위를 쓰지 않음. 액세스 토큰과 설치 토큰은 브라우저에 저장하지 않음. 설치용 매니페스트는 최소 범위(`drive`, `spreadsheets`, `documents`, `script.send_mail`, `script.external_request`, `userinfo.email`, Workspace만 `admin.directory.group.member`)로 올려 Gmail 접근을 요청하지 않음. 운영 매니페스트 `appScript/appsscript.json`은 아직 더 넓음([STATUS.md](./STATUS.md) 백로그) |
| 백엔드 설치 화면 | 1회용 설치 토큰이 있어야 실행. `installSystem`은 우리 학과 그룹 주소를 거부해, 새 기관 폴더가 다른 기관 구성원에게 공유되지 않게 함. 마법사가 주소로 넘기는 값은 클라이언트 ID와 그룹 JSON뿐이고 설치 토큰은 주소에 넣지 않음 |

## 3. 데이터 보호

| 대상 | 보호 방법 |
|---|---|
| 회원 이메일, 공지 작성자 이메일 | 저장 시 다층 변환 후 저장 (`EncryptionEmail.gs`) |
| 학생 연락처, 교직원 연락처·이메일 | 위와 같음 |
| 관리자 키 | 다층 변환 후 저장, 매일 교체 |
| Apps Script 웹앱 주소 | Netlify 서버 전용 환경변수 `APP_SCRIPT_URL`. 클라이언트 번들에 넣지 않음 |
| 공용 데이터 원본 | 배포 계정 드라이브. 역할 폴더별로 그룹에 공유. 공통 폴더(`notice`, `workflow`, `document`, `account`)와 `hp_member`는 그룹에 공유하지 않음 |
| 공지 첨부 | 링크 공개로 두지 않고 공개 범위 대상에게만 공유. 기존 첨부는 편집기에서 `applyNoticeAttachmentSharing`으로 다시 맞춤. 배포자가 관리할 수 없는 예전 사용자 소유 첨부는 건너뛰고 로그에 남김 |
| 액세스 토큰 | Apps Script는 요청자 확인에만 쓰고 저장·로그 기록하지 않음. 캐시 키는 토큰의 SHA-256 해시 |

현재 저장 시 변환은 Apps Script 안에 있는 알고리즘 조합입니다. 표준 암호화(키 관리가 분리된 AES 등)로 바꾸는 것을 개선 과제로 둡니다([§5](#5-개선-계획)).

### 공개되는 값

`VITE_`로 시작하는 환경변수는 빌드할 때 브라우저 번들에 들어갑니다. OAuth 클라이언트 ID, 폴더·시트 이름, 그룹 이메일이 여기에 해당하며, **공개되어도 되는 값만** 넣습니다.

## 4. 운영 보안 수칙

- Apps Script **배포 계정**은 학과 공용 계정으로 하고, 2단계 인증을 켭니다. 이 계정이 모든 공용 데이터의 소유자입니다.
- `hp_member` 스프레드시트는 배포 계정 외에 공유하지 않습니다.
- 퇴직·졸업자는 Google 그룹에서 빼고, `user` 시트의 `Approval`을 비웁니다.
- 스크립트 속성 `GOOGLE_CLIENT_ID`는 Netlify의 `VITE_GOOGLE_CLIENT_ID`와 같은 값이어야 합니다. 다르거나 비어 있으면 로그인한 모든 요청이 `AUTH_REQUIRED`로 거부됩니다. `/setup`의 "서버·사이트 클라이언트 ID 일치"로 확인합니다.
- 장부 폴더 공유는 장부 관리인과 필요한 그룹으로만 제한합니다. 저장된 접근 대상으로 권한을 다시 맞추려면 편집기에서 `applyLedgerSharing`을 실행합니다.
- 배포 계정의 Google 계정 권한 페이지에서 Apps Script 프로젝트 권한을 지우면 모든 웹앱 배포가 403을 돌려줍니다. 편집기에서 함수를 실행해 다시 승인합니다.
- 운영 빌드의 브라우저 로그는 경고·오류만 남깁니다. 디버그 로그가 필요할 때만 `localStorage`에 `HP_DEBUG`=`1`을 넣고, 확인 뒤 지웁니다.
- 관리자 키는 메일로만 전달하고, 메신저 등에 붙여 넣지 않습니다.
- 시트를 직접 수정할 때 암호화된 열을 평문으로 덮어쓰지 않습니다.
- 개인정보 처리 근거는 `/privacy`(개인정보처리방침), 서비스 조건은 `/terms`(이용약관)에 게시합니다.

## 5. 개선 계획

코드 점검(2026-10-27)에서 나온 보안 개선 과제의 **분류**입니다. 세부 내용과 우선순위는 비공개로 관리합니다. 서버 측 인가와 로그아웃 정리는 2026-10-30에 운영에 반영했습니다.

| 분류 | 방향 |
|---|---|
| 서버 측 인가 | **완료(2026-10-30 운영 반영).** Apps Script가 액세스 토큰으로 요청자를 확인하고, 관리 기능은 서버에서 관리자 여부를 다시 확인합니다([ADR-015](./ADR.md#adr-015-apps-script가-액세스-토큰으로-요청자를-확인한다)) |
| 화면 접근 | 페이지 단위로 권한을 검사합니다. 메뉴 숨김에만 의존하지 않습니다 |
| 개인정보 저장 | 표준 암호화 방식으로 바꾸고, 복호화는 필요한 서버 로직 안에서만 합니다 |
| 키 관리 | 관리자 키를 암호학적 난수로 만들고, 검증 로직을 하나로 합칩니다 |
| 로그인 방식 | implicit flow를 Authorization Code + PKCE로 바꿔 토큰 갱신과 세션 유지 시간을 개선합니다 |
| 오류 응답 | 운영 환경 오류 응답에서 스택·디버그 정보를 뺍니다 |
| 로그아웃 | **완료(2026-10-30 운영 반영).** 로그아웃할 때 계정별 캐시와 사용자 데이터를 지우고 진행 중인 요청을 정리합니다 |
